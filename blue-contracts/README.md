# Blue Contracts

Blue Contracts processes an event against exact managed Blue documents and returns
the resulting state, ordered emitted occurrences, deterministic gas and replay
evidence. It uses Language for content semantics and BEX for evaluation.

## Final gas edition

`1.0.0-final-gas.1` retains the existing tariffs and the 10,000,000-gas shared
maximum. Each charge is checked before work happens. Canonical outcomes contain
the final admitted gas total and, on exhaustion, one rejected-charge diagnostic.
They do not contain per-charge histories. Turn and unit proofs carry scalar gas
contributions, and continuation commitments carry totals and configured local
counters. Removing the history does not remove budget enforcement or replay
verification.

`SPECIFICATION.md` and `spec/contracts-final-gas.md` are the same normative text,
including eighteen executable Python modules. Source overrides and their hashes
are listed in `docs/sources.json`; the earlier reference remains frozen.
The 32 native type definitions are generated by the specification's catalogue
recipe. `types/` contains authoring inputs and `docs/types/` their exact views.

The specification, types, packages and receipts have new exact identities. A host
must explicitly install this edition. Keep the original runtime when replaying
old snapshots or histories; see [migration](MIGRATION.md).

## Local verification

With Python 3.13+, pytest, PyYAML, Java 21 and `BLUE_JAVA_CLASSPATH` pointing to
the qualified Java Language runtime and its dependencies:

```sh
./blue-package verify
./blue-package demo
./blue-package test
python ../tools/build_final_gas.py blue-contracts --check
```

The rebuild check compares the full archive, unpacked distribution and dependency
lock without modifying the selected publication. Package verification alone does
not certify a host implementation. [Qualification](QUALIFICATION.md) distinguishes
the new edition from earlier reference reports.
