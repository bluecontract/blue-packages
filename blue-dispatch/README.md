# Document Dispatch

Document Dispatch Policy evaluates a read-only BEX program once before each native channel delivery, using the current local document view and a runtime-owned dispatch binding containing kind, channel and operation. All installed policies must return an object with allowed Boolean and optional reason Text; policies run in canonical contract order without short-circuiting. A false decision skips every handler on that delivery. External inputs are still consumed and checkpointed, never deferred or replayed after policy changes. Embedded documents process independently; their installed updates precede the parent delivery under the existing native schedule. Only runtime-generated delivery kinds distinguish embedded and internal work from external messages. Decisions are committed in local completion evidence. Programs cannot emit events, change state or terminate processing. Ordinary BEX metering applies plus one dispatchPolicyCheck unit per policy. The binding is additive and opt-in by an exact declaration; documents without this declaration retain their dispatch semantics.

This candidate is an explicit native extension. Importing it alone does not grant authority or install code. Hosts must support the exact type and rules binding. The BEX decision belongs to the declaring document.

A denied request may publish native progress and independently processed child updates, but executes no handlers for that request. Its completion records `allowed: false`; Coordination records `DISPATCH_REJECTED` with the policy reason. Caller retries must be new requests. Canonical input ordering, authenticated provider history and dependency receiving remain unchanged.
