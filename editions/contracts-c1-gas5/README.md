# Contracts C1 + gas5 composition

This edition aligns the immutable Contracts specification with the C1 document
target correction and gas5 enum traversal already implemented by Java PR 4 and
Python PR 8. It introduces no additional business behavior. The Language
contracts-only/empty-value presence question remains outside this edition.

`recipe.json` pins the exact source inputs. `tools/build_contracts_gas5.py` uses
the existing locked package publisher and Language definition admission. It
replaces exactly the `channels.py` and `work.py` executable annexes, incorporates
the owning C1 and enum-order clauses, and selects the actual gas5 manifest while
checking that weights and the 100,000 maximum have not changed.
Coordination's imported-specification table binds the new complete Contracts
package specification hash; its other specification inputs remain unchanged.
Every one of the 148 exported definition bodies is compared with its predecessor
after only exact generated identity substitutions.

The Counter conformance example receives new authored/result identities and a
new gas5 receipt. Its original fixture and gas4 commitment remain immutable.
Generation requires the same result, emitted event, gas631 and complete314-row
gas trace as that independent predecessor vector; both consumers must then check
the successor's entire published observation and receipt. This prevents copying
old identity-dependent expectations into a new immutable archive.

The builder follows the selected import closure through Coordination, the
approved Mandates predicate/scalar source, Agreements, clauses, examples and
commerce functions. Root-clause packages form their own branch of that closure.
It regenerates exact dependencies and definitions from authored sources; it
does not overwrite a historical identity or infer native execution permission
from an available archive. Unchanged Language and BEX archives remain pinned.

From the package root, with the isolated Python environment installed:

```sh
/path/to/blue-python/.venv/bin/python tools/build_contracts_gas5.py \
  --python-source /path/to/blue-python \
  --output editions/contracts-c1-gas5/generated

# Read-only complete reconstruction; compare every generated byte.
/path/to/blue-python/.venv/bin/python tools/build_contracts_gas5.py \
  --python-source /path/to/blue-python \
  --output editions/contracts-c1-gas5/generated --check
```

The destination must be new. The generated `composition.json` records every
predecessor, successor, transport hash and identity mapping. Its
`nativeSupportApproved: false` is deliberate: each consumer must explicitly bind
these IDs to its existing implementation and qualify the exact composition.
Package construction alone is not native or publication acceptance.

`RELEASE-PIN.json` separately binds all 42 flat release assets, including the
exact ZIP, to the proposed immutable tag. After assembling a new candidate with
`tools/release.py assets`, the explicit `tools/release_pin.py record --assets
<directory> --tag blue-packages-2026.10.02.1` authoring step records those bytes.
Recording is not qualification. The release workflow always checks that pin
after assembly and before upload/publication; tag pushes must also match its
exact tag. A changed compression result, missing/additional asset or changed
payload fails closed. Checks never update the pin. Root must still review the
complete package/consumer qualification before publishing the tag.

The retained gas4 C1 candidate under `editions/contracts-exact-target` and all
previous distributions keep their original bytes. Saved contexts remain bound
to their original runtime; this edition supplies no data migration.
